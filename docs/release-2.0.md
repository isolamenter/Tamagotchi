# 大肥鱼 2.0 发布说明

日期：2026-10-21。状态：已提交并部署至生产，运行提交 `6d307d4`，未执行 Git push。正式回填、文件与业务验收见[部署记录](deployment-2.0.0-2026-10-21.md)。

## 本次变化

- 主程序统一为 `dafeiyu` 包，使用显式应用工厂，导入模块不初始化数据库。停止时跟踪并取消后台任务，关闭飞书与模型连接。
- 入站消息、回复编排、投递分别承担单一职责。bot 的 @ 不作为正文检索，近期双方发言完整保留，合并消息不重复、不混淆多人身份。
- 风格示例按已知场景约束选择；普通叫名字不触发身材辩解，技术吐槽不自动当成排障请求；相邻回复不重复注入同一示例。
- 自动梗图要求本轮原文证据、窄场景完整句式和回复文字同时符合实际图片，只开放邀饭／投喂、邀请摸鱼、直接身材调侃三类，歧义与多人合并拒绝。会话内至少间隔 9 条纯文字直接回复及 300 秒，重启不重置。
- 所有有效功能保留：直接回复、旁听、主动发言、梦境、日记、图片描述与生成、长期记忆、管理操作。
- 新后台按会话组织消息、记忆和发言操作，支持本地会话别名。切换会话隔离草稿并忽略过期响应，自动刷新保持阅读位置；发送状态清晰，移动端可使用全部操作。
- 运行库只支持全新的结构 2；无新旧结构双实现。移除养成状态、需求轮次、结算、领奖、互动按钮等旧业务。

## 新库结构与回填

- `conversations`：会话标识、展示名称、创建时间、压缩进度与明确的调度状态列。
- `messages`：会话外键、说话人、内容、时间、旁听标记、来源、回复模式及实际发送的梗图标签。
- `memories`：会话外键、三种记忆类型、内容、人物、时间线索与压缩来源进度。
- `memory_embeddings`：每段记忆唯一向量，含 provider、model、dimension，外键与字节数约束。
- `style_embeddings`：当前风格文档的内容哈希、类型和模型缓存。
- `user_names`、`event_dedup`、`sys_cache`：独立的称谓、去重和临时缓存。
- `published_cards`：已发布内容卡，不包含养成或结算字段。

一次性工具只读旧库，写入不存在的新目标文件，不覆盖已有文件。它保留原会话、消息、记忆 ID 与关联，逐表比较数量和内容摘要，检查 SQLite 完整性、外键和压缩标记。失败时数据事务回滚，目标保持“迁移未完成”的版本标记，运行服务会拒绝打开；需人工查看失败原因并使用新的目标路径重试。

旧向量没有可信的 provider/model 来源，不伪造标签导入。回填后使用明确的向量重建命令，按现有批次大小生成文档向量；所有向量生成成功且原记忆未改变时，才进行事务替换。该步骤会调用实际 embedding 服务，未完成前后台显示待构建数量。

```bash
python3 -m dafeiyu.tools.migrate --source /path/to/old-snapshot.db --destination /path/to/dafeiyu-v2.db --report /path/to/import-report.json
python3 -m dafeiyu.tools.reembed --database /path/to/dafeiyu-v2.db --env-file .env
```

不导入临时凭证缓存、旧养成字段、养成结算卡或未发布卡片；保留已发布的内容卡，排除项写入报告。原库保留，不能把新空库当成“已完成回填”。

## 正式部署前的顺序

本次已按用户明确授权执行以下部署顺序，结果见部署记录。本节不构成对未来部署、数据切换或回滚的持续授权。

1. 本地验收完成，检查实际改动，提交本次文件，记录准确 commit。重新生成发布包，要求 `working_tree_dirty=false`，与提交内容一致，不使用未提交的本地候选包部署。
2. 只读检查生产目录、当前服务启动命令、依赖、磁盘与旧库状态；明确新代码 staging、新库、报告、备份路径及短暂停机窗口。
3. 上传并核对仅含运行文件的包，逐文件验证大小／SHA-256；不上传或覆盖旧 `state.db`，不修改 Tunnel、SSH 或其他服务。当前 `requirements.txt` 已新增 `python-dotenv`：在预检确认的 2.0 独立虚拟环境中安装依赖，验证模块导入和运维 CLI 可用，再进入停机窗口；安装或验证失败不停止旧服务、不切库。原虚拟环境保留作为恢复材料。
4. 按批准的窗口停止旧服务写入，生成一致的旧库快照。运行回填到新文件，核对报告、内容摘要、数量、外键及完整性；重建记忆向量并核对待构建数为 0。失败时不切换。
5. 明确配置独立 `GM_TOKEN`，将 `STATE_DB` 指向已验证的新库，将本服务的 ASGI 启动命令改为 `dafeiyu.app:create_app --factory`。新目录采用明确清单部署，避免把旧源码继续混在新运行包里。
6. 启动后验收服务、本地与公网 `/healthz`、启动日志、后台认证和数据浏览。以获准的测试目标分别验证真实模型、风格索引、记忆召回、图文投递、主动发言及定时路径；健康接口不代替业务验收。
7. 保留源库、快照、迁移报告、原启动配置和原代码。任何删除、回滚或数据库恢复，按仓库规范列出精确目标、影响与恢复方式并获得确认后执行。

## 未验收项与风险

- 梗图误发及频率问题已在本地 2.0 修复并通过针对性测试，保守规则会漏掉部分合适的自由表达；真实模型 JSON、图片上传和 webhook 已通过，实际群聊效果尚未人工验收。实现与发布包记录见[实施记录](meme-frequency-fix-plan.md)，修复已随本次 2.0 上线。
- 生产回填与真实向量重建已经核验；多轮自然度、记忆召回质量及实际群内投递尚未人工验收，不能承诺已消除 AI 感。
- 完整保留近期双方历史会增加模型输入成本；语料门槛与相邻重复控制仍不能覆盖所有语义复读。
- 飞书发送与 SQLite 写入没有跨系统事务，进程中断或发送结果不明时仍有已发未记、重复操作的窗口。
- 迁移不可信旧向量会要求全量重建，生产窗口需要留出实际接口耗时；旧库的异常数据会明确中止导入。
