# 0002：有证据的人物记忆与 schema 3 离线迁移

记录时状态：审核分支实现，尚未部署。承接 [0001](0001-schema2-offline-migration.md) 的“新文件离线迁移、不改原库”原则，不改写历史决策。本文不追踪当前生产版本。

## 决策

平台账号 ID 与会话共同定义人物键；模型只能整理这些 ID 的别名、关系、偏好与事件，不合并账号。名字/报告人/主体/引文必须区分。个人信息与普通记忆共享 memories 表，增添证据、主体、报告人、置信度、稳定事实键、期限与 supersession；别名断言保留历史。每日整理和对外日记/梦境分开，原始消息独立保留。

2026-10-28 实现细化：日记草稿与记忆改为同一次整理调用产出，并复用 schema 3 既有 `sys_cache` 同事务保存；发布仍独立调度，日记不进入人物事实证据。当前规则见[记忆规格](../specs/memory.md#同批日记)，不改变本决策的事实隔离与离线迁移边界。

schema 3 是显式版本边界。运行时仅接受空文件新建或完整 v3；v1/v2 必须使用 `python -m dafeiyu.tools.migrate --source <只读快照> --destination <不存在的新文件> --report <新报告>`。工具不启动服务、不调用模型、不修改原库，不复制 sys_cache 凭据；验证逐表计数/哈希、外键、消息水位与完整性。失败目标留在不可运行版本，不能手工改版本强行启用。

v2 原有消息/卡片/向量原样保留；v1 沿原迁移规则保留可迁移内容。旧 user_names 留作审计，旧卡片的主体保持空。旧文本没有人类文本/自动识图分界，只能产生待确认线索，不能单独确认本人事实。v2 向量按原 provider/model/dimension 保留，换模型仍须单独授权重建；v1 无兼容向量则不伪造。

## 审核后运维步骤（本次未执行）

1. 停写或取得一致快照，保留原代码与原库；在副本上跑迁移并人工检查报告与抽样。
2. 使用 fake 集成先验配置；确认模型上下文能力与每日额外预算，个人资料隐私边界与不确定提示。
3. 获准后才将新代码及 STATE_DB 切向新文件，单 worker 运行。
4. 回退须停新服务后恢复旧代码 + 保留的旧库快照。新库运行后新增消息/身份不能靠降 user_version 回灌旧库；需要另行审核的导出/合并方案。不要覆盖任一原文件。

## 边界

批次/字符/日调用数/超时/重试均有界；无新消息零整理调用。任务失败不推进事实水位，明确空结果可推进。对外参与仍有静默、显式定时窗口、活跃度、冷却、去重与模型批准，不把“自然”误解为取消安全限制。单进程锁不是分布式任务队列。

离线测试只证明结构与流程，不证明模型能可靠理解全部反讽/引述/昵称；真实模型准确率、延迟与费用需另行评测。记录时本分支未推送、未部署、未访问生产库。
